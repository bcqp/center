Validation log

How each series was checked against its official release.

Each row in the validation table represents a series or observation checked against its cited source record. Validation is specific to the indicator, period, unit, source vintage and retrieval date shown; it is not a blanket certification of the dataset or producing institution.

Validation protocol and audit trail

Validation is a documented comparison between a value used in BCQP analysis and the corresponding value in the cited publisher's release. The procedure draws on established statistical quality principles, including transparent concepts, source documentation and reproducible processing. The World Bank's data quality guidance and the UN National Quality Assurance Framework provide external reference points. BCQP's checks are its own procedures, not a formal DQAF assessment.

01

Identify the statistical object

Confirm the exact indicator name, unit, population or institutional coverage, frequency, reference period and price or index base. Similar labels may describe different statistical concepts. Consult the source metadata and definitions before comparing values.

02

Locate the primary release

Use the original statistical agency or central-bank release where available. Record the publication title, table or series identifier, release date, URL and retrieval date. For Bangladesh, relevant primary portals include BBS, Bangladesh Bank and the Finance Division.

03

Reproduce the observation

Read the exact period and unit, apply only documented conversions, and compare the resulting figure with the value stored in the register. Retain source precision before display rounding. Record any conversion formula, deflator, exchange-rate convention or aggregation rule.

04

Check revisions and breaks

Review footnotes, base-year changes, rebasing, seasonal adjustment, revised historical observations and methodological notes. Record discontinuities that affect interpretation. The IMF dissemination metadata and source-agency release notes can help identify definitions and compilation changes.

05

Record the result

Retain the source URL, retrieval date, observation period, value, unit, source vintage, check outcome and explanatory note. If the match cannot be established, mark the observation as pending rather than verified. Where a mismatch is found, investigate rounding, revisions, unit conversion and coverage before deciding whether the value can be used.

Validation outcomes

  • Verified: the value matches the cited source for the stated period and unit under the documented comparison rule.
  • Pending: the source, release, definition or observation cannot yet be confirmed.
  • Revised: a newer source vintage changes the previously recorded value or historical series.
  • Not comparable: the candidate series differs in definition, coverage, unit or reference period and cannot be treated as the same statistical object without adjustment.
  • Derived: the reported figure is calculated from source inputs; the formula and inputs must be recorded rather than compared as if it were a directly published value.

Revisions, breaks and derived data

A successful source match does not establish that the statistic is free of measurement error. Statistical agencies may revise preliminary observations, rebase indices or change classifications. BCQP should retain the retrieval date and, where possible, a versioned copy or source citation for the vintage used. For derived values, the validation record must include the input series, formula, transformation and any interpolation or imputation. The UN SDG metadata repository illustrates the importance of indicator-specific definitions, methods and source documentation.

What validation does not establish

Validation does not establish causal validity, model correctness, representativeness beyond the source's sampling design or fitness for every research question. Those issues require separate methodological assessment. A value may match the official release exactly and still be unsuitable for a particular estimand or model.

How to report a check

A transparent validation statement identifies the source, dataset or table, indicator, reference period, unit, retrieval date and result. If the value differs from a previously downloaded vintage, state which vintage was used and why. If the source is inaccessible or metadata are incomplete, disclose that limitation instead of asserting verification.
