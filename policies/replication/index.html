Replication policy

How results can be repeated.

Purpose and commitment

BCQP aims to make published quantitative results inspectable and, where data access and licensing permit, computationally reproducible. Replication materials should allow a reader to understand how source data were transformed, how a model was specified and how reported tables or figures were generated.

Minimum replication documentation

  • Publication title, authors, version and package date.
  • Source datasets, release identifiers, retrieval dates, licences and access restrictions.
  • Data-cleaning, merging, transformation and sample-construction code.
  • Model equations, variable definitions, options, lag structure, priors or identifying restrictions where relevant.
  • Software, package and engine versions, random seeds, estimation settings and convergence criteria.
  • Scripts linking reported tables and figures to the analysis.
  • Instructions for running the workflow and known limitations.

Use of Open Econometric Systems

Where a BCQP analysis uses an estimator implemented in Open Econometric Systems (OES), the publication should identify the model, options and version or implementation used. Where the analysis uses software or methods outside OES, the relevant environment and procedure should be documented instead. OES is not represented as supporting every method used in BCQP research.

Data access and legal limits

Publicly accessible data should be cited with a direct source link and retrieval date. Data should not be redistributed where licence, confidentiality or access terms prohibit it. For restricted data, provide code and instructions that can run on an authorised local copy without exposing protected observations. The FAIR principles provide a reference for responsible data findability, accessibility, interoperability and reuse.

Computational detail

Bayesian analyses should document priors, chains, warm-up, draws and convergence diagnostics. Optimisation-based estimation should document starting values, objective function, tolerances and convergence status. Stochastic procedures should record random seeds where feasible. Differences caused by software updates, numerical precision or revised source data should be reported.

Archiving and exceptions

Where appropriate, versioned packages may be archived using services such as Zenodo. If full replication is impossible, the publication should explain why and identify what can be reproduced. The American Economic Association data and code policy is an external reference for empirical documentation, not a certification of BCQP packages.
